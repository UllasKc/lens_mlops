# Lens MLOps: the app

The Databricks App behind Lens MLOps: a Node/Express server built on Databricks AppKit (`server/`) and a static, framework-free UI (`public/`). It is deployed by `deploy/deploy.py --only app` from the repository root; see the root [README](../README.md) and [SETUP_GUIDE](../SETUP_GUIDE.md). Databricks builds the app on deploy, so Node.js is only needed to work on it locally.

## How it fits together

| Part | Uses |
|---|---|
| Command Center, Explorer | Certified gold views through the SQL warehouse (`server/lib/sql.ts`), cached in memory per data version |
| Assistant | The Genie space ("Lens query engine"), Chat and Agent modes (`server/lib/genieRun.ts`, `agentMode.ts`) |
| Chat history, usage log, answer cache, evaluations, conversation memory | Lakebase Postgres, schema `chatapp` (DDL in `deploy/lakebase/schema.sql`) |
| Guardrails, faithfulness judge, follow-ups, Auto mode, platform answers, memory summaries, empty-result notes | Databricks model serving endpoints, configured through `LENS_AI_CONFIG` (written into `app.yaml` by the deploy) |

The app runs as its own service principal: users need only `CAN_USE` on the app, with no direct access to the data, Genie or Lakebase.

| Path | Contents |

| `server/server.ts` | App setup: AppKit plugins (Genie, Lakebase), routers |

| `public/index.html`, `public/css/style.css` | The four tabs and dialogs; styles |
| `public/js/home.js` | Command Center (five chapters, model and alert lists) |
| `public/js/explorer.js` | Explorer |
| `public/js/chat.js` | Assistant |
| `public/js/monitoring.js`, `observability.js`, `evals.js`, `responsible.js` | Observability and its areas |
| `public/js/app.js`, `export.js`, `notify.js`, `voice.js` | Tabs, account menu and tooltips; PDF export; notifications; voice input |
| `app.yaml` | Generated by `deploy.py` on every app deploy; local edits are overwritten |

## API

| Route | Purpose |
|---|---|
| `GET /api/me` | Signed-in user's name and email |
| `GET /api/dashboard/summary`, `/overview` | Command Center figures |
| `GET /api/dashboard/models?list=…&value=…` | The models behind a Command Center figure (fixed lists; values checked against the data) |
| `GET /api/dashboard/alerts?incident=…` | The alerts behind one incident, minute by minute |
| `GET /api/explorer/options`, `/data` | Explorer filter values and figures |
| `GET /api/explorer/models?<filters>&flag=…` | The models behind an Explorer chart item |
| `GET/POST/PATCH/DELETE /api/chat/sessions[/:id]` | Chat sessions |
| `POST /api/chat/sessions/:id/messages` | Ask a question (server-sent events: progress, answer, follow-ups) |
| `POST /api/chat/route` | Auto mode: Quick answer or Deep analysis for a question |
| `GET /api/chat/suggestions` | Suggested questions (the same list is pre-warmed) |
| `GET/POST /api/chat/messages/:id/…` | An answer's trace and feedback |
| `GET /api/admin/usage`, `/insights`; `PATCH /api/admin/feedback/:id` | Observability |
| `GET /api/evals`, `POST /api/evals/runs`, … | Evaluations |
| `GET /api/ai/transparency` | Responsible AI: models, features and configuration |

## Run it locally

You need Node.js 22+, a Databricks CLI profile for the workspace, and the deployed resources (Genie space, warehouse, Lakebase). Set the same environment variables the deploy writes into `app.yaml` (for example `DATABRICKS_GENIE_SPACE_ID`, `DATABRICKS_WAREHOUSE_ID`, `LENS_GOLD_SCHEMA`, the `PG*` Lakebase settings including `PGUSER` (your workspace email) and optionally `LENS_AI_CONFIG`), plus `DATABRICKS_CONFIG_PROFILE` and `DATABRICKS_APP_PORT`, in a `.env` file (git-ignored), then:

```bash
npm install
npm run dev        # server with reload, on DATABRICKS_APP_PORT
npm run typecheck  # TypeScript check of the server
```

On Windows `npm run dev` fails (`NODE_ENV=...` is not valid in cmd); run the server directly from Git Bash instead:

```bash
NODE_ENV=development npx tsx --tsconfig ./tsconfig.server.json --env-file-if-exists=./.env ./server/server.ts
```

Locally you are signed in as a development user, and pre-warming can be switched off with `LENS_PREWARM=off` to avoid engine calls. Section 12 of the [SETUP_GUIDE](../SETUP_GUIDE.md) has the details.

## Notes for changes

- Record every change in the root `CHANGELOG.md`: what changed, why, and what was verified.
- The Command Center and Explorer must keep reconciling: with no filters, the Explorer's totals equal the Command Center's, and every model list matches the number on its card.
- Figures come from certified views only; don't compute business figures in the browser or with a model.
